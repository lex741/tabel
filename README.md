# Табель рабочего времени

Веб-приложение для учёта рабочего времени по категориям задач: таймер, ручной ввод, отчёт «что было сделано за рабочий день», архив дней, итоги недели и месяца в таблицах и страница с диаграммами.

Фронтенд статический (HTML, CSS, JavaScript без сборки), поэтому его можно опубликовать на GitHub Pages. Данные и вход хранятся в [Supabase](https://supabase.com) на бесплатном тарифе. Так один и тот же аккаунт работает на всех устройствах.

## Что внутри

```
index.html            точка входа
css/styles.css        стили (светлая и тёмная тема по настройке системы)
js/config.js          настройки: адрес и ключ Supabase
js/utils.js           даты, форматирование, CSV
js/api.js             работа с данными (Supabase или localStorage)
js/app.js             интерфейс и страницы
supabase/schema.sql   таблицы и правила доступа для Supabase
```

Страницы: **Трекер** (таймер, записи за сегодня, отчёт за день, категории), **Архив дней** (прошлые дни по месяцам, отчёты и записи можно править), **Итоги недели и месяца** (таблица «категория × дни/недели», ревью периода, отчёты по дням, экспорт CSV), **Результаты** (кольцевая диаграмма и столбцы по категориям за неделю, месяц, год или всё время).

Категории по умолчанию: Работа над таргетом, Создание контент-плана, Постинг контента, Созвоны, Обучение, Мелкие оперативные задания. Свои категории добавляются из выпадающего списка «Над чем работаете» (пункт «+ Добавить категорию…»). Цвет любой категории меняется на странице «Трекер» в блоке «Категории».

## Быстрая проверка без настройки

Откройте `index.html` в браузере. Пока `js/config.js` не заполнен, приложение работает в локальном режиме: вход `admin` / `admin123`, данные хранятся только в этом браузере. Это режим для проверки, синхронизации между устройствами в нём нет.

## Развёртывание: Supabase + GitHub Pages

### 1. База данных и пользователь в Supabase

1. Зарегистрируйтесь на supabase.com и создайте проект (New project, регион ближе к вам, например Frankfurt).
2. Откройте **SQL Editor → New query**, вставьте содержимое `supabase/schema.sql` и нажмите **Run**.
3. Откройте **Authentication → Users → Add user → Create new user**:
   - Email: `admin@tabel.app`
   - Password: `admin123`
   - включите **Auto Confirm User**.
4. Откройте **Authentication → Sign In / Providers** (в старом интерфейсе **Providers → Email**) и выключите **Allow new users to sign up**. Иначе любой, кто найдёт сайт, сможет создать себе аккаунт через API.

Логин `admin` на форме входа автоматически превращается в `admin@tabel.app`. Если хотите другой домен, поменяйте `LOGIN_EMAIL_DOMAIN` в `js/config.js`. Можно вводить и полный email.

### 2. Ключи в config.js

В Supabase откройте **Project Settings → API** (или **Data API**) и скопируйте **Project URL** и **anon public** key. Вставьте их в `js/config.js`:

```js
SUPABASE_URL: 'https://xxxxxxxx.supabase.co',
SUPABASE_ANON_KEY: 'eyJhbGciOi...',
```

Anon key задуман публичным: он лежит в коде любого сайта на Supabase. Данные защищают правила RLS из `schema.sql` (каждый видит только свои строки) и пароль. **service_role** key в код не кладите никогда.

### 3. GitHub Pages

```bash
git init
git add .
git commit -m "Табель рабочего времени"
git branch -M main
git remote add origin https://github.com/<ваш-логин>/tabel.git
git push -u origin main
```

В репозитории на GitHub: **Settings → Pages → Build and deployment → Source: Deploy from a branch**, ветка `main`, папка `/ (root)`, **Save**. Через минуту-две сайт будет доступен по адресу `https://<ваш-логин>.github.io/tabel/`.

После этого в Supabase откройте **Authentication → URL Configuration** и укажите этот адрес в **Site URL**. Для входа по паролю это не обязательно, но так Supabase не будет ссылаться на localhost.

## Безопасность

Пароль `admin123` слабый, а сайт на GitHub Pages открыт всему интернету. Подобрать такой пароль несложно. После первого входа смените его в Supabase: **Authentication → Users → admin@tabel.app → Reset password** или через SQL. Если репозиторий публичный, не храните пароль в коде и в README.

## Как устроены данные

- Время относится к дню, когда отрезок начался. Отрезок 22:00–01:30 целиком попадёт в день начала.
- Неделя начинается в понедельник. Месяц в итогах разбит на недели «по понедельникам», первая и последняя обрезаны границами месяца.
- Запущенный таймер хранится в базе. Его видно на всех устройствах, второй таймер параллельно запустить нельзя.
- Другие устройства подтягивают изменения при возвращении на вкладку и раз в две минуты.
- Скрытая категория пропадает из выпадающих списков, но её время остаётся во всех итогах. Удаления категорий нет намеренно, чтобы не терять историю.
- Напоминания об итогах появляются на странице «Трекер» с пятницы по воскресенье (итоги недели) и в последние два дня месяца (итоги месяца), а в начале следующей недели или месяца, если итоги так и не заполнены.

## Если что-то не работает

- **«Неверный логин или пароль»**: проверьте, что пользователь создан с Auto Confirm и что email совпадает с `логин@LOGIN_EMAIL_DOMAIN`.
- **Supabase не принимает email на выбранном домене**: создайте пользователя на реальном адресе и входите, вводя полный email.
- **Ошибки «relation does not exist» или «permission denied»**: `schema.sql` не выполнен целиком, запустите его ещё раз (он идемпотентный).
- **Бесплатный проект Supabase засыпает** после недели без запросов. Разбудить его можно кнопкой Restore в панели Supabase, данные при этом не теряются.
